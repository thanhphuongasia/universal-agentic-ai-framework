🗺️ UAAF Framework Overview

Universal Agent Architecture Framework — monorepo của các packages Python để xây dựng AI agents production-ready. Mỗi package độc lập, implement một protocol rõ ràng, có thể swap implementation mà không đổi code business logic.
Design principle

Protocol-first

Mọi layer đều có IXxx protocol. Code của bạn phụ thuộc vào interface, không phải concrete class → swap backend không cần refactor.

Design principle

Open/Closed

Extend bằng cách thêm (new registry entry, new class). Không bao giờ sửa existing logic để accommodate variant mới.

Design principle

Registry pattern

Provider, backend, adapter đều qua registry. Thêm provider mới = 1 dòng trong list. Zero changes elsewhere.

Luồng request production

User message
    ↓
RequestHandler.handle()          ← ryuu-runtime: single entry point
    ↓
StrategySelector → strategy_id   ← ryuu-runtime: cognitive strategy selection
    ↓
LLMIntentAnalyzer → difficulty   ← ryuu-intent: classify query complexity
    ↓
HookRegistry.pre_execute()       ← ryuu-hooks: PII scrub, rate limit check
    ↓
LLMAgent._react_loop()           ← ryuu-execution: tool-calling loop (canonical)
    ├── ILLMProvider.complete()  ← ryuu-providers-*: Anthropic / OpenAI
    ├── MemoryToolset.recall()   ← ryuu-knowledge-memory: cross-session context
    └── MCPTool.call()           ← ryuu-mcp-client: external tools
    ↓
HookRegistry.post_execute()      ← ryuu-hooks: cost tracking, audit log
    ↓
AgentResult → OutgoingMessage    ← ryuu-messaging-core: send to channel

⚙️ Core Types & Protocols

Foundation của toàn bộ framework. Không có dependency nào khác — tất cả packages khác import từ đây. Định nghĩa types, error hierarchy, và Null implementations.
Context

ExecutionContext

Models

Data classes chuẩn cho input/output của mọi agent call. Cost track input/output tokens + USD.

ryuu-runtime depends: ryuu-core

🔄 Runtime — Request Routing

RequestHandler.handle() là entry point duy nhất cho mọi production request. Không gọi agent.execute() trực tiếp — nó bypass cognitive tier, không có strategy_id trong context.
from ryuu_runtime import RequestHandler, StrategySelector

handler = RequestHandler(
    strategy_selector=selector,
    agent_pool=pool,
    hooks=hook_registry,
)

result = await handler.handle(task)  # ← dùng cái này, không gọi agent trực tiếp
ClassVai trò
RequestHandlerOrchestrates: hooks → strategy selection → agent execution → hooks
StrategySelectorMaps intent → strategy_id (REACT, PARALLEL_FANOUT, EVALUATOR_OPTIMIZER...)
LLMIntentAnalyzerLLM-based query classification → StructuredIntent với difficulty + topics
ryuu-workflow v0.2.0a1

🔀 Workflow Engine

Multi-step workflow với state machine, checkpoint persistence (resume sau crash), và status tracking.
WorkflowEngine

Run + resume workflows

Chạy workflow từ đầu hoặc resume từ checkpoint. Track status: PENDING → RUNNING → COMPLETED / FAILED.

StateMachine

State transitions

Định nghĩa states + transitions. Engine validate transition hợp lệ trước khi execute.

from ryuu_workflow import WorkflowEngine, FileCheckpointStore, Workflow

engine = WorkflowEngine(
    checkpoint_store=FileCheckpointStore("~/.ryuu/checkpoints"),
)

workflow = Workflow(states=[...], transitions=[...])
result = await engine.run(workflow, initial_state="start", context=ctx)
# Nếu crash giữa chừng → engine.resume(workflow_id) tiếp tục từ checkpoint
ryuu-cognitive

🧠 Cognitive — AI Strategies

Các primitive để tăng chất lượng LLM output: compaction (shrink long history), query decomposition, expansion, và verifier.
LLMCompactor

Conversation compaction

Shrink conversation history khi quá dài. LLM summarize các turns cũ thành 1-2 paragraphs. Giữ nguyên N turns gần nhất.

LLMQueryDecomposer

Query decomposition

Tách compound query thành sub-queries độc lập. Ví dụ: "so sánh A và B theo tiêu chí X" → 3 SubQuery objects.

IVerifier

Output verification

Verify agent output trước khi return. VerificationResult có passed/failed + reason. Plug vào HookRegistry.

Lưu ý quan trọng Cognitive strategies (Plan-then-Execute, Best-of-N, Reflection) đều wrap quanh _react_loop(), không thay thế nó. ReAct là execution primitive — LLM gọi tools. Cognitive strategy là cách orchestrate nhiều ReAct calls.
ryuu-intent

🎯 Intent Analysis

LLMIntentAnalyzer classify query → StructuredIntent: difficulty (trivial/medium/hard), topics, và suggested strategy. StrategySelector dùng kết quả này để chọn model và cognitive strategy.

from ryuu_intent import LLMIntentAnalyzer, normalize_difficulty

analyzer = LLMIntentAnalyzer(provider=anthropic_provider)
intent = await analyzer.analyze("So sánh PostgreSQL và MongoDB cho OLAP workload")
# intent.difficulty = "hard"
# intent.topics = ["database", "analytics", "architecture"]
ryuu-reasoning

⚖️ Reasoning — Formal Constraints

Z3Verifier dùng SMT solver (Z3) để verify LLM output thỏa mãn formal constraints. RuleVerifier dùng Python rules đơn giản hơn.

from ryuu_reasoning import RuleVerifier, Rule

verifier = RuleVerifier(rules=[
    Rule("price_positive", lambda r: r["price"] > 0),
    Rule("discount_valid",  lambda r: 0 <= r["discount"] <= 100),
])
result = await verifier.verify(agent_output)  # VerificationResult
ryuu-execution

🤖 Execution — Agents & Tools

LLMAgent._react_loop() là implementation duy nhất cho production. Gọi provider với tools=[...], loop trên stop_reason=="tool_use" cho đến end_turn.
ClassDùng khi
LLMAgentSingle agent với tool-calling. Canonical implementation.
AgentPoolFan-out nhiều agents song song (PARALLEL_FANOUT strategy).
ToolRegistryRegister tools để agent gọi. Validate input schema tự động.
BaseAgentExtend khi cần custom agent không phải LLM.
from ryuu_execution import LLMAgent, ToolRegistry

registry = ToolRegistry()
registry.register(my_tool_fn)  # any async function với type annotations

agent = LLMAgent(
    provider=anthropic_provider,
    tool_registry=registry,
    max_iterations=8,
)
result = await agent.execute(task)  # AgentResult
ReActStrategy là academic demo ReActStrategy (text-parse DONE:/ACTION:) chỉ để minh họa paper ReAct 2022. Không dùng trong product code. Tool-calling JSON qua provider API là cách đúng.
ryuu-hooks v0.3.0a1

🪝 Hooks — Lifecycle Injection

Inject behavior vào agent lifecycle mà không subclass. Pattern: register handler → framework gọi tại đúng lifecycle event.
Pre/Post Execute

Request-level hooks

Chạy trước/sau toàn bộ agent execution. Dùng cho: auth check, rate limit, cost budgeting.

Pre/Post LLM

LLM call hooks

Wrap từng LLM call. Dùng cho: PII scrub trên prompt, response filtering, token counting.

Pre/Post Tool

Tool call hooks

Wrap từng tool call. Dùng cho: approval gate (HITL), audit log, result caching.

from ryuu_hooks import HookRegistry, HookEvent

registry = HookRegistry()

@registry.on(HookEvent.PRE_LLM)
async def scrub_pii(ctx: PreLLMContext) -> None:
    ctx.request.messages = [
        replace(m, content=remove_pii(m.content))
        for m in ctx.request.messages
    ]

@registry.on(HookEvent.ON_BUDGET_EXCEEDED)
async def handle_budget(ctx: OnBudgetExceededContext) -> None:
    await notify_admin(f"Budget exceeded: {ctx.scope_key}")
ryuu-guardrail

🛡️ Guardrail — Safety Pipeline

Pipeline kiểm tra input/output của agent. Mỗi IGuardrail trả GuardrailResult với action: ALLOW / BLOCK / WARN.

from ryuu_guardrail import GuardrailPipeline, GuardrailAction

pipeline = GuardrailPipeline(guardrails=[
    ToxicityGuardrail(threshold=0.8),
    PIIGuardrail(trust_level=TrustLevel.EXTERNAL),
])

result = await pipeline.check(user_input)
if result.action == GuardrailAction.BLOCK:
    return "Yêu cầu bị từ chối."

ryuu-knowledge-rag

🔍 Knowledge RAG — Document Retrieval

RAG pipeline đầy đủ: chunk documents → embed → store vector → retrieve by cosine similarity. Dùng cho knowledge base tĩnh (docs, FAQ, codebase).
Ingestion

RAGPipeline

Input: raw text → RecursiveChunker → embed via ILLMProvider → InMemoryVectorStore.

Retrieval

DenseRetriever

Query embedding → cosine similarity → top-K chunks. RAGBackbone wrap lại thành IKnowledgeBackbone.

from ryuu_knowledge_rag import RAGPipeline, RAGBackbone, InMemoryVectorStore

pipeline = RAGPipeline(embedder=provider, vector_store=InMemoryVectorStore())

backbone = RAGBackbone(pipeline=pipeline, retriever=DenseRetriever(vector_store))
ctx = await backbone.assemble_context("How to configure rate limiting?", scope_key="docs")
ryuu-knowledge-memory v0.3.0a2 Quality layer mới

🧩 Knowledge Memory — Cross-session Context

3-tier memory system: Working (session buffer) → Episodic (long-term observations) → Semantic (distilled facts). Tự động filter noise, consolidate qua LLM, và evict theo decay.

Ba tầng nhớ

Working

WorkingMemoryStore

Session buffer. FIFO max 50. Sync write. Scope: session.

Tốc độ cao In-memory hoặc ICollectionStore
▼ promotes to
Episodic

EpisodicMemoryStore

Long-term observations. Max 500. Keyword overlap scoring. Async write qua ExtractionFilter.

active → consolidated → archived JsonlCollectionStore / Postgres
▼ consolidates to
Semantic

SemanticMemoryStore

Distilled facts. No limit. Cosine + keyword. Written by DreamingConsolidator post-session.

Không expire Embedding dedup ≥ 0.92

Mỗi tầng lưu vào đâu? Sync hay async?

TầngStore mặc địnhStore persistentWriteKhi nào ghi
Working in-memory deque (FIFO 50) ICollectionStore
(Sqlite / Jsonl)		 SYNC await inline trong backbone.write() — luôn ghi, không lọc
Episodic in-memory dict (max 500) JsonlCollectionStore
/ PostgresCollectionStore		 ASYNC (có filter)
SYNC (không filter)		 Có ExtractionFilter → ensure_future (background, không block response). Không filter → await inline
Semantic in-memory dict
chưa có collection		 — chưa persist ASYNC Post-session: end_session() → ensure_future(run_cycle) → DreamingConsolidator ghi
2 giới hạn WIP — phải biết trước khi wire vào production ① SemanticMemoryStore hiện chỉ in-memory (không nhận tham số collection). Facts đã distilled mất khi restart process.
② Lifecycle của episodic (get_unconsolidated / mark_consolidated / archive / eviction) chỉ đọc in-memory _store. Khi truyền collection=, store() ghi thẳng vào collection và không populate _store → consolidation + eviction thấy 0 entry. Docstring ghi rõ: "in-memory only; collection backend: subclass".
→ Nghĩa là persist (collection) và consolidate (dreaming) hiện loại trừ nhau trong cùng một episodic store. Bot phải chọn một, hoặc viết subclass collection-backed cho các method lifecycle.

Quality Layer (optional)

from ryuu_knowledge_memory import MemoryBackbone
from ryuu_knowledge_memory.consolidator import (
    ExtractionFilter, DreamingConsolidator, EvictionJob
)

backbone = MemoryBackbone(
    layers=[WorkingMemoryStore(), episodic_store],
    processor=ExtractionFilter(llm=provider),           # signal/noise filter

)

# Khi session kết thúc

# → async: EvictionJob.run() + DreamingConsolidator.run_cycle()

EvictionJob — importance-weighted decay

# score = importance_base × (0.95 ^ days_idle)
# high=1.0 → không bao giờ evict
# medium=0.6 → decay to 0.10 sau ~55 ngày
# low=0.3 → decay to 0.10 sau ~37 ngày
# score < 0.10 + status=consolidated → DELETE
# score < 0.10 + status=active → ARCHIVE 30 ngày

MemoryToolset — LLM tools

from ryuu_knowledge_memory import MemoryToolset

Bot B — production (persistent + quality layer)

Persist qua JSONL/Postgres + ExtractionFilter lọc noise + DreamingConsolidator distill. Gọi end_session() khi turn/phiên kết thúc.

from ryuu_knowledge_memory import (
    MemoryBackbone, WorkingMemoryStore, EpisodicMemoryStore,
    SemanticMemoryStore, MemoryToolset,
)
from ryuu_knowledge_memory.consolidator import ExtractionFilter, DreamingConsolidator
from ryuu_storage_jsonl import JsonlCollectionStore

ROOT = "~/.ryuu/memory"
episodic = EpisodicMemoryStore(max_entries=500)         # in-memory → dreaming chạy được
semantic = SemanticMemoryStore()                        # in-memory (chưa persist)

backbone = MemoryBackbone(
    layers=[
        WorkingMemoryStore(collection=JsonlCollectionStore(root_dir=ROOT, table="working")),
        episodic,
    ],
    processor=ExtractionFilter(llm=provider),           # async signal/noise filter
    dreaming_consolidator=DreamingConsolidator(
        episodic=episodic, semantic=semantic,
        llm=provider, embedder=provider,
    ),
)
toolset = MemoryToolset(backbone=backbone)

# mỗi turn — bind scope rồi chạy agent
async with toolset.bind(scope_key="botB:user42:telegram"):
    result = await agent.run(message=user_input)

# khi session kết thúc → eviction + consolidation chạy background
await backbone.end_session("botB:user42:telegram")
scope_key = ranh giới cách ly Quy ước: "<bot>:<user>:<channel>". Hai bot khác prefix → không bao giờ đọc trúng memory của nhau, dù dùng chung process hay chung storage backend. Cùng user trên 2 channel (Telegram vs CLI) cũng tách được nếu muốn, hoặc dùng chung "<bot>:<user>" để nhớ xuyên kênh.
Bot B muốn vừa persist episodic vừa dreaming? Hiện chưa được trong cùng store (xem 2 giới hạn WIP ở trên). Nếu để EpisodicMemoryStore(collection=...), consolidation/eviction sẽ no-op. Hai lối ra: (a) giữ episodic in-memory như ví dụ trên — accept mất khi restart; hoặc (b) viết subclass collection-backed override các method lifecycle. ryuu_sensei hiện đi hướng persist (collection) nên dreaming chưa kích hoạt.

Chi tiết từng tiêu chí

✅ Nhỏ gọn — Modular install

Chỉ install những gì cần

Mỗi package độc lập. Dùng memory không cần cài providers-anthropic. Dùng eval không cần cài messaging.

pip install ryuu-knowledge-memory  # chỉ memory
pip install ryuu-eval-core          # chỉ eval runner
# LangChain: pip install langchain → kéo 40+ transitive deps
✅ Zero deps ở core

ryuu-core không có dependency nào

Foundation package hoàn toàn độc lập. Không pydantic, không numpy, không tiktoken. Chỉ Python stdlib.

So sánh: LangChain core kéo pydantic + tenacity + requests ngay cả khi không dùng HTTP.

⚠️ DX — Cần học Protocol pattern

Consistent nhưng có learning curve

Sau khi hiểu IKnowledgeBackbone, ILLMProvider, IMemoryStore — tất cả components hoạt động theo cùng 1 pattern. Không có surprise.

LangChain: API thay đổi nhiều lần (v0.1 → v0.2 → v0.3), LCEL syntax mới, LangGraph tách riêng → context switch liên tục.

✅ Registry = mở rộng không đau

Thêm provider/backend = 1 dòng

✅ Null implementations

Test không cần mock phức tạp

Mọi protocol có NullXxx implementation: NullCostTracker, NullAuditLogger, NullRateLimiter, NullTracer. Unit test inject Null → không cần unittest.mock.patch khắp nơi.

⚠️ Vendor lock của Agent SDKs

Claude SDK & OpenAI SDK: single provider

Tốt cho simplicity, nhưng nếu cần switch provider (cost, latency, capability) phải rewrite toàn bộ integration layer. UAAF: swap AnthropicProvider → OpenAIProvider = 1 dòng config.

Vết xe đổ của LangChain — UAAF tránh thế nào

❌ LangChain: Runnable[Any, Any]

Type system bị phá vỡ

Mọi component đều là Runnable[Any, Any]. IDE không biết output của bước trước là gì. Runtime error thay vì compile-time.

✅ UAAF: CompletionRequest → Response, Task → AgentResult — typed end-to-end.

❌ LangChain: SequentialChain cho mọi thứ

Over-abstraction

5 class để chain 3 functions. CompositeProcessor, SequentialChain, RouterChain... tất cả có thể thay bằng function calls đơn giản.

✅ UAAF: 3 cases tương tự mới abstract. Không abstract sớm.

❌ LangChain: ConflictResolver tại write-time

LLM hallucinate conflict không có thật

Detect conflict bằng LLM mỗi lần ghi = expensive và unreliable. LLM có thể quyết định sai.

✅ UAAF: conflict resolve tại query-time — assemble_context() trả cả hai, LLM tự xử lý với đầy đủ context.

❌ LangChain: breaking changes mỗi minor version

Upgrade = rewrite

v0.1 → v0.2 → v0.3: LCEL syntax mới, callback system mới, LangGraph tách riêng. Code cũ không chạy.

✅ UAAF: protocol-first. Implementation thay đổi không break consumer code. ILLMProvider stable.
